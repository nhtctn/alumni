Current Week: 07

> Prepare basic UIs for job posting and application pages

**Title:** Add Handlebars job and application pages

**Acceptance Criteria:**

- [x] Users can browse job postings in a list and open a job detail page.
- [x] Authorized page flows expose create and edit job-posting forms.
- [x] Users can submit an application from a job page.
- [x] Users can view their application list and statuses.
- [x] Invalid, missing, and failed service results render the existing error/not-found patterns.
- [x] Existing API routes and announcement/user pages remain unchanged.

**Subtasks:**

1. [x] Add server-rendered job-posting list, detail, and create/edit view routes.
2. [x] Add job-posting Handlebars templates using the existing page conventions.
3. [x] Add server-rendered application submit and user application-list routes.
4. [x] Add application Handlebars templates for form, list, empty, error, and not-found states.
5. [x] Wire form actions to the existing job-posting and application services without duplicating business logic.
6. [x] Verify route parameters, form payloads, validation failures, and service errors.

**Decisions:**

- Use NestJS Handlebars views because the repository already has server-rendered user and announcement pages.
- Include job list, detail, and create/edit forms to cover browsing and posting.
- Include application submission and user application status/list views.
- Keep the work limited to basic UI and existing service/API capabilities; defer authentication and authorization enforcement.

**Technical Notes:**

- Extend the existing non-API controller pattern and exclude new page controllers from Swagger.
- Reuse `JobPostingsService` and `ApplicationsService`; do not add frontend dependencies or an Angular scaffold.
- Follow the existing `backend/views/users` and `backend/views/announcements` template structure and shared styles.
